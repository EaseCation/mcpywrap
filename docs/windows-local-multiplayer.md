# Windows 本地自动联机

WindowsBackend 的本地组默认采用自动加入；用法以 [双客户端技能](../skills/mcpywrap/references/dual-clients.md) 为准。macOS、外服 connect 和远程执行协议不复用本适配层。旧组未记录 join_mode 时继续使用手动方式。

## 端口与引擎兼容

NetherNet 的主机监听可以从 7551 回退到临时端口，但默认发现不覆盖所有同机主机。工具在主机就绪后取得其网络身份，并核对所属进程唯一的 IPv6 通配 UDP 监听端口；多个候选会被拒绝，不将 Safaia、OreUI 或配置中的目标端口当作 LAN 监听端口。

需要非默认端口时，`lan_locator` 使用运行映像的 PE x64 展开表确定函数边界，再反汇编匹配 TransportConfiguration 初始化：16 位端口字段、相邻广播周期、协议 magic 和对象传参必须同时成立，且候选必须唯一。不维护引擎版本/RVA 表，不复用另一个二进制的地址，也不将任意匹配到的 7551 字节视作指令。

`lan_memory` 只操作 worker 刚创建的本地客机，核对 PID 创建时间及可执行文件身份。写入时暂停该进程，复核原指令，只更新端口立即数，读回校验并恢复原页属性、恢复线程。失败会结束本次客机；主机保留。磁盘游戏文件始终不改写，进程退出后适配消失。

此识别方式已覆盖 3.9.0.350466、3.9.0.401155 和 3.10.0.436581。相同结构的新构建会自动定位；机器架构、配置结构或代码生成方式超出识别条件时必须失败，不保证任意未来引擎都无需算法更新。定位器的离线测试仅使用人工生成指令，不分发游戏代码、内存快照或修改后的游戏文件。

## 自动加入与就绪

Safaia 的普通脚本执行依赖进入世界后才初始化的游戏系统。自动客机在隔离角色资料中复用一个工具引导世界，待通道就绪后自动保存退出，再完成目标世界选择和资源下载。此阶段的物理 HUD 标记仅供内部通道就绪判断，不能向组发布 world_ready。

菜单由会话所属窗口的后台 WGC 画面提供，Windows OCR 返回当前文字及物理坐标。选择目标采用主机玩家标识，拒绝截断、任意编辑距离或多个候选；只规范化已知像素字形混淆。输入前重新观察布局，限定一次动作并安排引擎内抬起；不移动系统鼠标，不抢前台。未知请求不重放，停滞、不可识别菜单或超时保留诊断并结束自动操作。

只有客机进入目标网络 ID 和目标世界的 HUD，才发布 world_ready；随后原有 GroupMonitor 核对双方不同玩家与主机服务端名单，发布 connection_verified。自动加入期间，公共客机 Python/热更/输入请求被拒绝，组热更仍要求所有成员世界就绪。明确未发送的只读探针争用保留最近一次验证及原时间戳；真正观察到离开或身份不符会清除验证。

worker 是 session.json 的唯一写入者；自动加入线程单独维护 local-join.json 与最近的 local-join-menu.json。状态包含 initializing、leaving_setup、finding_host、joining、joined、failed、cancelled。公共组响应增加 joining 状态，Qt、CLI、smoke 和重启流程共用它。停止会话或主机身份变化会取消自动操作，只清理所属进程。

## 验证与维护

菜单覆盖中文和英文，依赖 Windows 可用的 OCR 语言及持续渲染的游戏窗口；识别失败没有前台输入回退。引导世界每个角色至多一个，并与项目世界、真实账户资料隔离。组资源热更的现有限制不因自动加入而改变。

维护入口为 [测试指南](../tests/README.md) 中的可选四端实机程序。应同时验证两个项目的 Mod 客户端/服务端系统加载、网络与世界隔离、客机重启、另一组保持连接以及停止清理；只观察窗口、进程存活或端口变化不足以确认联机成功。
