# 玩家动作与连续队列

严禁业务代码依赖 `mcpy.*`：这些方法仅存在于临时注入的调试会话，正常游戏运行环境不提供它们；业务实现须使用正式 ModSDK 或项目框架。

`runtime install` 一次注入 `mcpy.ui`、`mcpy.player`、`mcpy.api`。玩家层通过同一个客户端 Python 通道执行，支持本地或远程会话，不需要取得服务器控制权。服务端代码只用于隔离测试世界准备和效果验收，没有作为普通玩家动作的实现。

日常 API、默认时长、坐标/槽位约定、连续计划示例及失败恢复统一维护在 [Skill 玩家操作说明](../skills/mcpywrap/references/runtime-player.md)，主 Skill 直接列出了常用方法，不要求 Agent 自行检索 ModSDK。

全部输入入口的键名、别名、组合/边沿写法与平台兼容见 [按键写法与兼容对照](../skills/mcpywrap/references/input-writing.md)。

## 实现边界

- 公共 ModSDK 用于状态读取、朝向、移动向量锁定、跳跃。内部 `localplayermodule` 用于真实客户端攻击、选槽、使用物品、挖掘和释放，按实际函数是否存在报告能力，不按引擎版本号限制。接口缺失或调用异常会返回引擎版本与兼容性提示。
- 鼠标负键码不使用内部键盘模拟；键盘调用成功不能证明方块交互已发生。玩家层改用真实语义入口，并让 key 拒绝鼠标键码。
- 食物/弓开始使用时，原生调用可能返回 False 但 `local_player_is_using_item()` 为 True；封装按真实使用状态继续保持并定时释放。只根据布尔返回值会错误地中断进食或蓄力。
- `attack / dig / use_item / eat / shoot` 使用 30 秒有效的玩家快照。执行时核对玩家、维度、手持物品、选槽及瞄准目标。准星射线可能返回几十格外的方块，因此还必须与玩家实际 GetPickRange 比较，不能把“射线命中”当成“可交互”。
- 所有持续输入有上限和自动释放；离开 HUD 时停止。只释放控制层记录的输入，不无条件清空用户或其他 Mod 的全部状态。锁屏、最小化或引擎不执行 tick 时的调度不作保证。
- 普通弓已适配；弩的装填与发射、实体喂食/交易尚未适配，明确报错。没有通过系统键鼠自动兜底。
- 第三人称相机位置不等于玩家视点，距离和 look_at 使用玩家 GetPos，另行返回 camera 供诊断。队列在看向动作后重新核对角度；若外部控制覆盖朝向，停止后续步骤。潜行使用原生 UI 的 ChangeSneakState，而不是只适用于特定输入模式的内部 setSneaking。

## 连续计划

计划先校验动作、参数和时长，按序在游戏定时器执行。每步获取新状态；攻击和使用物品自动绑定该步快照，可附加 expected slot/item/target 条件。输入未释放前不开始下一步，且队列占有执行权期间拒绝其他 UI/玩家写操作。

队列统一由共享时间编排器生成 `at_ms`，省略时根据前一步的计划结束与 `delay_ms` 自动计算，显式时间使用同一执行流程。返回补齐时间的 `plan` 以及步骤的 `started_ms / finished_ms`。不再人为追加 100 ms 间隔；游戏 tick 的调度精度仍不适合 Windows 快切测量，后者使用 [Windows 输入编排](input-sequence.md)。

单步输入最多 10 秒，计划最多 32 步、120 秒（包括排时空隙），总执行上限 125 秒，含 5 秒调度余量。等待和步骤前延迟单次最多 10 秒。每步保留精简前后状态，队列失败停止后续步骤，不回滚已完成的消耗或世界变化。整个计划和单步动作均使用幂等操作 ID；未知结果通过 status 查询，不重发。

`completed` 只说明输入流程完成，`effect_verified=false` 保留给上层根据饥饿值、物品数量、位置、目标生命值或服务端日志判断。尤其是挖掘时限耗尽，不等于目标已被破坏。原目标坐标已经变为空气时，`block_removed_observed=true / verification=client_block_readback` 表示客户端读到了方块消失，队列可以继续；不等同于已证明由本次操作造成了服务端变化。

## 按键时间线与动作提交

独立按键重叠使用新增 `runtime player timeline` / `mcpy.player.timeline(plan)`，公开契约见 [后台按键时间线](../skills/mcpywrap/references/runtime-key-timeline.md)。同一时刻严格遵循列表顺序，不采用旧 key 的修饰键排序；默认迟到继续并记录，可显式设置 max_lateness 中止。每个计划独占已有写操作槽位，取消/异常只释放本计划持有的键，失败释放可用 stop 重试。接口通过同一客户端 Python 通道，原 sequence 保持串行。

统一安装源码超过单条 32 KiB 限额时分段暂存，确认各段后才执行安装；暂存不注入部分控制器。查询及业务包不依赖暂存模块，不扩大原传输上限。输入消费阶段、暂停期间释放和人工输入归属均不作额外保证，不把脚本回调计数包装为模拟 tick。

攻击、放置及物品使用的开始阶段统一交给游戏脚本 tick 执行，避免 JNI 客户端回调发生在引擎交互阶段之外时只出现动画或被拒绝。首次返回 pending 后仍查询原 operation；等待期间取消不会补发动作，开始前重新核对目标、物品、端侧场景和交互距离。completed/accepted 仍只表示动作调用完成，真实伤害、消耗和方块变化需另行观察。

挖掘期间复用客户端 Player.Swing 播放原版挥手，动画请求与挖掘进度共用定时器，结束或取消后不再请求。缺少该 API 的引擎保留挖掘能力并报告 swing_supported=false；动画请求成功不代替方块状态验证。

测试入口见[测试说明](../tests/README.md)。
