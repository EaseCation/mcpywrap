# 玩家动作与连续队列

严禁业务代码依赖 `mcpy.*`：这些方法仅存在于临时注入的调试会话，正常游戏运行环境不提供它们；业务实现须使用正式 ModSDK 或项目框架。

`runtime install` 一次注入 `mcpy.ui`、`mcpy.player`、`mcpy.api`。玩家层通过同一个客户端 Python 通道执行，支持本地或远程会话，不需要取得服务器控制权。服务端代码只用于隔离测试世界准备和效果验收，没有作为普通玩家动作的实现。

日常 API、默认时长、坐标/槽位约定、连续计划示例及失败恢复统一维护在 [Skill 玩家操作说明](../skills/mcpywrap/references/runtime-player.md)，主 Skill 直接列出了常用方法，不要求 Agent 自行检索 ModSDK。

## 实现边界

- 公共 ModSDK 用于状态读取、朝向、移动向量锁定、跳跃。内部 `localplayermodule` 用于真实客户端攻击、选槽、使用物品、挖掘和释放，按构建及函数是否存在报告能力。
- 鼠标负键码不能简单交给内部键盘模拟；实测返回成功却没有放置方块。玩家层改用真实语义入口，并让 key 拒绝鼠标键码。
- 食物/弓开始使用时，原生调用可能返回 False 但 `local_player_is_using_item()` 为 True；封装按真实使用状态继续保持并定时释放。只根据布尔返回值会错误地中断进食或蓄力。
- `attack / dig / use_item / eat / shoot` 使用 30 秒有效的玩家快照。执行时核对玩家、维度、手持物品、选槽及瞄准目标。准星射线可能返回几十格外的方块，因此还必须与玩家实际 GetPickRange 比较，不能把“射线命中”当成“可交互”。
- 所有持续输入有上限和自动释放；离开 HUD 时停止。只释放控制层记录的输入，不无条件清空用户或其他 Mod 的全部状态。锁屏、最小化或引擎不执行 tick 时的调度不作保证。
- 普通弓已适配；弩的装填与发射、实体喂食/交易尚未适配，明确报错。没有通过系统键鼠自动兜底。
- 第三人称相机位置不等于玩家视点，距离和 look_at 使用玩家 GetPos，另行返回 camera 供诊断。队列在看向动作后重新核对角度；若外部控制覆盖朝向，停止后续步骤。潜行使用原生 UI 的 ChangeSneakState，而不是只适用于特定输入模式的内部 setSneaking。

## 连续计划

计划先校验动作、参数和时长，按序在游戏定时器执行。每步获取新状态；攻击和使用物品自动绑定该步快照，可附加 expected slot/item/target 条件。输入未释放前不开始下一步，且队列占有执行权期间拒绝其他 UI/玩家写操作。

单步输入最多 10 秒，计划最多 32 步、120 秒。等待和步骤前延迟单次最多 10 秒。每步保留精简前后状态，队列失败停止后续步骤，不回滚已完成的消耗或世界变化。整个计划和单步动作均使用幂等操作 ID；未知结果通过 status 查询，不重发。

`completed` 只说明输入流程完成，`effect_verified=false` 保留给上层根据饥饿值、物品数量、位置、目标生命值或服务端日志判断。尤其是挖掘时限耗尽，不等于目标已被破坏。

## 验证

`tests/test_runtime_player.py` 使用有时序的引擎适配器验证：按键逆序释放、移动/疾跑恢复、目标变化与越距拒绝、食物 False 返回但已开始使用、弓蓄力松开、队列延迟、预检失败、步骤断言、取消、重复请求和调用者修改原计划后的隔离。

实机验收脚本为 `tests/manual_runtime_player.py`。先准备独立生存世界、未满的饥饿值、快捷栏食物/普通弓及箭，再运行 `--project <项目> --session <sid> --food-slot 3 --bow-slot 4 --output <新JSON> --require-background`。脚本通过公开 CLI 提交并验证队列，消耗一份食物和一支箭，恢复原朝向和选槽；不会创建物品、改变游戏模式或停止传入会话。

2026-10-03 在引擎 `3.10.0.420447` 的独立本地世界验证：

- 后台数字键切换快捷栏，移动向量限时执行后归零，直接朝向正确改变准星目标。
- 客户端真实攻击后，服务端读到目标生命值 10 → 5。
- 使用手持圆石后，服务端读到目标面相邻位置由空气变为圆石；挖掘后恢复空气。
- 一次提交“选苹果 → 吃 → 等待 → 选弓 → 看向 → 射箭”：全部步骤完成；服务端饥饿值 10 → 14，苹果 3 → 2，箭 16 → 15。
- 瞄准测试实体射箭后，服务端 `ActuallyHurtServerEvent` 记录到来源为本地玩家、带有效 projectileId 的 `cause=projectile`，实际伤害为 9，确认了真实投射物伤害。

实机结果仅说明该构建及测试场景成立；不同服务端规则、网络延迟、物品和 Mod 行为仍应按 Skill 核对效果。

结构化证据见 [玩家验收记录](validation/runtime-player.json)：包含当次注入源码摘要、吃/射队列、十步移动流程、服务端投射物伤害及 UI 共存回归。历史记录用于追溯；当前发布回归按 [开发验证](development.md) 与 [发布流程](releasing.md) 执行。
